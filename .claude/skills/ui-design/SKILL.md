# UI Design

## Rules

- Understand the existing application design before changing UI.
- Reuse existing components, styles, tokens, and patterns.
- Do not introduce unnecessary libraries.
- Keep layouts responsive across desktop, tablet, and mobile.
- Use consistent spacing, typography, colors, and component states.
- Support loading, empty, error, disabled, hover, focus, and success states.
- Follow accessibility best practices.
- Avoid unnecessary animations and visual complexity.
- Do not redesign unrelated screens.
- Keep UI changes consistent with the existing product.

## Workflow

1. Inspect the relevant UI files.
2. Identify existing design patterns.
3. Plan the smallest required change.
4. Implement using existing components where possible.
5. Check responsive behavior.
6. Check accessibility.
7. Verify the final result.

## Token Efficiency

- Read only files relevant to the requested UI change.
- Do not scan the entire repository unnecessarily.
- Do not explain obvious code.
- Do not create unnecessary files.
- Do not repeat project information already available.
