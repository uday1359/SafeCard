# Project Understanding

## Rules
- Always read README.md and relevant documentation first.
- Understand the build system and package manager in use.
- Identify the core framework and architecture pattern (e.g., MVC, Microservices).
- Map out the folder structure conceptually before proposing massive changes.

## Workflow
1. Read project root configuration files.
2. Review top-level documentation.
3. Identify entry points of the application.
4. Formulate an understanding of how components interact.

## Token Efficiency
- Do not output the entire README contents back to the user.
- Only search for configuration files relevant to the current task.
